このループの読み方
各エージェントの出力が次のエージェントの入力になる連鎖を、起点 → 観測 UI → ループ戻りの順で示す。 実行は sideBScheduler の各ジョブ (周期駆動) がトリガー。組成 (DiscoveryAgent の EdgeLedger 書き込み) は DISCOVERY_COMPOSE_ENABLED 既定 OFF で、有効化すると本ループが完全に閉じる。

① ループ全体図 (起点 → ハンドオフ連鎖 → UI → 戻り)

⏱ 起点: sideBScheduler (FX 平日 24h)
入力源: 市場開場時刻 / 各ジョブの周期タイマー。最初の実データ入力は MarketDataService (EODHD All-In-One) の OHLCV / indicators。
監視ループ TradeMonitoringJob (1h) が常時稼働し、その約定→ノートが下流 (組成→検証→進化) の入力源になる。
↓PlanGenerationJob (4h 周期 / 既定 ON)
② Plan フェーズ — AIOrchestrator.generatePlan
入力: symbol / OHLCV / indicators (+ 上位足 higherTFData)　出力 → AITradePlan + scenarios (DB 永続化、MTF: 執行足+上位足を付与)
ResearchAI LLM ← OHLCV/indicators ／ → marketAnalysis (regime/trend/levels)
Lens Aggregation 決定論 ← OHLCV ／ → LensFeatureSnapshot (primaryTimeframe 付き)
EdgeLedger Matching 決定論 ← lensSnapshot ／ → 成立中の既存仮説 ID 群
IndicatorSpecialist LLM ← MTF (執行足+上位足) bundle ／ → テクニカル解釈
PlanAI (StrategyThinker) LLM ← research + lens + indicator 解釈 ／ → scenarios (entry/SL/TP)
BullBearDebate LLM ← candidate scenarios ／ → 優勢方向 (preferredDirection)
Debate Hookup 決定論 ← 優勢方向 ／ → 採用方向を付与した最終 scenarios
↓createTradeFromPlan
③ 執行フェーズ — VirtualTrade → AITradeNote
入力: AITradePlan の scenario　出力 → AITradeNote (+ reflection)、plan の MTF 文脈を継承
VirtualTrade 生成 決定論 ← scenario ／ → pending トレード (timeframe/higherTimeframe 付き)
TradeMonitoringJob 決定論 ← 1分足 OHLCV ／ → pending→open→closed の状態遷移 (高安値検証)
aiNoteService 決定論 ← 決済済 trade + plan ／ → AITradeNote (MTF 付き)
reflectionAI LLM ← trade 結果 (時間足込み) ／ → 振り返り分析 (note.learnings に統合)
↓DiscoveryJob (日次 / 7日 rolling lookback / 既定 ON)
④ 組成フェーズ — DiscoveryAgent (Step D-4) 書き込みは DISCOVERY_COMPOSE_ENABLED 既定 OFF
入力: 直近 7 日の AITradeNote を (symbol, timeframe) ごとにグループ化　出力 → EdgeHypothesis (source='discovery', unverified)
aggregateFeatureValues / 特徴量分離 決定論 ← AITradeNote 群 ／ → 勝敗を分ける特徴量
DiscoveryAgent.analyze LLM ← 特徴量 + 過去の confirmed/rejected (feedback loop) ／ → 新規仮説。symbol/timeframe はノート実値からクランプ
HypothesisGenerator dormant 旧組成役。再設計で Discovery に統合され休止 (呼び出し 0)
↓EdgeLedger (status で進行管理)
⑤ 検証フェーズ — 2 段ゲート
入力: EdgeHypothesis (unverified)　出力 → confirmed / rejected
ScreeningJob 既定 ON 軽量 BT ／ unverified → screening_passed / rejected
FullValidationJob 既定 ON 機械判定 本格 BT + WF + MonteCarlo + BuyHold ／ screening_passed → confirmed / rejected (旧 StrategistAgent の LLM 判定は廃止)
⑥ 進化フェーズ — EvolutionLoop
入力: confirmed 仮説 + 12 novelty seed　出力 → promotion (採用戦略)　EvolutionJob 既定 OFF
MutationAgent LLM ← 親戦略 ／ → インジ params 最適化変異体 (Step D-2)
CrossoverAgent LLM ← 親A の負けトレード ／ → フィルタ追加でエッジ発見 (Step D-3)
Surrogate → 本格 BT 決定論 Rescue Lane で候補を ~7 件に絞り analysis-engine で本格 BT → promotionCandidates
↓EdgeLedger / AITradeNote の集計を API が供給
⑦ UI 出力担当 — LedgerDashboardController / aiNoteController
入力: EdgeLedger (status/category/source) + AITradeNote　出力 → frontend dashboard (/side-b/dashboard)
/stats/overview 全体サマリ ／ /stats/time-series confirmed 推移 ／ /stats/by-category ／ /stats/validation-activity ／ /discovery/latest ／ /discovery/funnel = Discovery 組成 funnel (Step D-4b) ／ /system/health
↺ ループ戻り: 採用戦略・確定仮説が次サイクルの Plan / EvolutionLoop の親プールに還流。新しい AITradeNote が翌日の Discovery 組成入力になり、組成仮説の検証結果が feedback loop で次回組成に注入される。

④ 一貫して流れるもの: MTF 文脈 (執行足 + 上位足)

Step D 前提の基盤修正 (#277/#278) で、timeframe (執行足) + higherTimeframe (上位足) が plan → trade → note → reflection ハンドオフ → 組成 を一貫して流れるようになった。 DiscoveryAgent はこの実 timeframe を仮説にクランプするため、「分析した銘柄/足と無関係な仮説を組成する」過去の不整合が構造的に起きない。 原則は src/side-b/AGENTS.md に明文化済 (エージェント出力 / ハンドオフは symbol と同格で MTF 文脈を必須とする)。

⑤ 現状の閉ループ条件

Plan→Trade→Note→検証→進化→UI の各ハンドオフは結線済。唯一の開口部は組成の書き込みゲート DISCOVERY_COMPOSE_ENABLED (既定 OFF)。これを true にすると DiscoveryAgent が AITradeNote から仮説を組成して EdgeLedger に流し込み、/discovery/funnel パネルで「組成 → screening → confirmed/rejected」を観測しながら ループが完全に閉じる。有効化はデータと観測を見ながら判断する。
凡例: LLM=大規模言語モデル判定 / 決定論=純粋計算・機械判定 / GATE=env フラグ制御 / dormant=コード残置・呼び出し 0。本図は概念フローであり、行番号レベルの正本はソースを参照。
