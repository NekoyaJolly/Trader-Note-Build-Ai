01

ポジショニング — Side-A と Side-B の責務分離

Trader-Note-Build-Ai は人間向けと AI 向けの 2 サブシステムで構成される。Side-B は 「AI が自律的に市場を観察し、仮説を立て、検証し、エッジ台帳を育てながら運用するシステム」へ段階進化させていく領域。

MVP 完成

Side-A — TradeAssist (人間向け)

トレード履歴からの自動ノート生成、リアルタイム市場データとの一致判定、通知 + 発注支援 UI。

段階進化中

Side-B — TradeAssistant-AI (AI 向け)

AI による日次トレードプラン生成、仮想トレード実行・記録、AI 用ノートによる学習ループ。本ドキュメントの対象。

設計の正本: /AGENTS.md → /src/side-b/AGENTS.md → /src/side-b/adk/AGENTS.md。 作業着手前に必ずルートの最優先 5 原則を確認すること。

Strategy DSL — JSON 戦略言語

エージェントの出力する戦略はテキストではなく構造化 JSON。Mutation / Crossover / Backtest 全てがこのスキーマを共通言語にする。

StrategyDSL の骨格 
interface StrategyDSL {
  id: string; name: string; description: string;

  entryFilter: {
    conditions: Array<{
      indicator: string;
      operator: '<' | '>' | '=' | 'between';
      value: number;
    }>;
    logic: 'AND' | 'OR';
  };

  exitRules: {
    takeProfit: { pips: number };
    stopLoss:   { pips: number };
    trailingStop?: { pips: number };
    timeExit?:     { barCount: number };
  };

  riskManagement: {
    positionSize: number;
    maxDailyLoss: number;
  };

  source: 'manual' | 'mutation' | 'crossover' | 'human';
  generation: number;
  parentIds?: string[];
  fitness?: { pf: number; sharpe: number; winRate: number };
}

採用する範囲

Runner / SequentialAgent / ParallelAgent / LoopAgent / FunctionTool / Tracing。すべて既存ロジックを 合成でラップするのみ。

採用しない範囲 (既存維持)

撤退基準 (1 つでも該当したら撤退)

設定 / モデル選択

エージェントごとに利用 LLM を差し替え可能。reasoning モデル向けの maxTokens 集約は PR #204 で 10 万ベースに引き上げ済み。

per-agent モデル設定

config.ai.models.<key> + modelFor() + 環境変数 AI_MODEL_<KEY>。 グローバルデフォルトは AI_MODEL。

maxTokens 集約

ハードコード 7 箇所を /src/config/aiTokenLimits.ts 周辺に集約 (PR #204)。 reasoning モデルは 10 万ベース。

プロンプト管理

/src/side-b/prompts/ に 24+ の .md を配置。 __global__.md / __specialist_common__.md を全エージェントに合成。 PromptRegistry が動的読込 + マクロ注入 (日付・シンボル等)。

外部 .md 化の意義

進化的探索の 変異対象にプロンプト自体を含めるため、コード文字列リテラルではなくファイルとして版管理する。

ts-node の .ts/.json 同名衝突: 同ディレクトリの同名 .ts/.json は ts-node で .json が優先解決され TS export が undefined 化する。 サブディレクトリ分離 + fs.readFileSync が安全。
