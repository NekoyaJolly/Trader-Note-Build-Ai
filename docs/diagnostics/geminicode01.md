# Context
現在、進化ループ（Evolution）およびPDCAサイクルを司る `Side-B` システムにおいて、並列実行バグや本番環境特有の問題により、AIの学習プロセスが約10日間停止しているという致命的な障害が発生しています。
私はコードの読み書きを行わずにAIに実装を委ねる「バイブコーディング」で開発を行っているため、あなたが提供されたコードベース（Repomix）全体を深く解析し、根本原因の特定、見落としの発見、および具体的な修正コードの提示までを自律的に完遂する必要があります。

## 現状把握している問題点リスト

### 🔴 致命的 (= 進化機能が動かない原因)
1. **Evolution の並列実行バグ**
   - `setInterval(15min)` + `lastEvolutionRun` (完了時セット) の組合せで、実行が15分を超えると次のtickが二重起動してしまう。
   - 実証: 19:05:48 と 19:20:56 で同じ EURUSD/15m 1年分のfetchが並列発生。結果、DB接続競合で処理が詰まり完走しなくなる。
2. **Productionでログが抑制される**
   - `this.log()` が `if (!this.isProduction)` でガードされており本番環境（Cloud Run）でno-opになるため、Evolutionがどのphaseで詰まっているか全く見えない。
3. **EdgeHypothesis の confirmed が増えていない**
   - 5/1以降 0件 (= 約10日進化停止)。PDCAは同じエッジしか参照できず学習ループとして機能していない。

### ⚠️ 設計の歪み (= 構造問題)
4. **Evolution と PDCA の結合が暗黙的**
   - 設計上は EdgeHypothesis テーブル経由の疎結合だが、実装ではEvolutionのstateがPDCAから見えない。`notifyPdcaEvolutionGeneration` は thinking log を残すだけで、詰まっても通知されない。
5. **runEvolutionNow / lastEvolutionRun の命名と実態の乖離**
   - 名前は「24h cron 相当」を意図しているが、実態は完了時刻ベースの fire-and-forget timer になっており破綻している。状態管理 (= IDLE か RUNNING か) が無い。

### ⚠️ 設定の永続化漏れ
6. **`--no-cpu-throttling` が CI/CD に未反映**
   - Cloud Runのバックグラウンド処理維持のため手動適用済みだが、デプロイ設定（deploy.yml等）に未反映のため次回のデプロイで消えてしまう。

### 📝 既知の改善余地 (= 緊急ではない)
7. Evolution の seed symbol が `seedDescriptor.ts` 等で `EURUSD` にハードコードされている。
8. Cold start 直後5秒のみ Prisma の pool timeout が発生する。
9. 市場休場時の cTrader 取得失敗ログが大量に出てノイズになっている。
