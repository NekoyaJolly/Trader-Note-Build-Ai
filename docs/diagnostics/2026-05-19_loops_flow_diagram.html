横断する設計原則 / 既知の不整合

設計原則 (= 守られている)
・役割別細分化: Phase 6.7a 以降は agent ごとに専用 prompt (md ファイル外部化 + PromptRegistry 進化)
・外部 analysis-engine 一本化: BT engine はアプリ全体で 1 つ (analysis-engine + backtesting.py、別コンテナ)
・役割侵食防止: Discovery と Evolution は EdgeLedger に直接書かない (= 過去のバグ修正)
・strategy DSL 不変式: Evolution が探索する単位 = DSL JSON。EdgeHypothesis とは別軸
⚠ 既知の不整合 (= 議論対象)
1. 同じ analysis-engine endpoint (/v1/screening-backtest) を ScreeningOrchestrator と EvolutionLoop の両方が叩く が結果分布が大きく違う (削除後集計: Screening は全 not_testable、Evolution は formalBtPassed 82%)。経路差を要調査
2. reflectionAIService / researchAIService は Phase 5.5 経路のまま = loadPrompt 直呼び、PromptRegistry 未対応。進化対象から外れている
3. PDCALoop の state handler 内部は ADK trace なし = 1-A の 7 state 遷移は監視できない。ADK 統合は sideBOrchestrator 経由 skill のみカバー
4. Plan 多段 flow (1-B) は AIOrchestrator が一括実行 = 6 段の各 agent 内部に ADK trace なし、step 単位の観測ができない
5. 本来 Plan の中身は AgentLoop が担う設計だった (Phase 5.5) が 2026-05-19 撤去済 (PR #231)。現在は AIOrchestrator.generatePlan が代替実装、Orchestrator 層 (= 上位統括 LLM) は未実装
