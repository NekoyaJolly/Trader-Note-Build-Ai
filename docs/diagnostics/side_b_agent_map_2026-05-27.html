🗑 アーカイブ対象 (= 一旦外す)

分かりにくくなる原因のエージェント、3 件を Nekoさん 指示でアーカイブ:
  • MetaEvolutionAgent: 手動 CLI のみ、自動統合なし → アーカイブ class 削除 or コメント化 + prompt 削除
  • PromptMutationAgent: 月次プロンプト進化 → アーカイブ Job も含めて削除/コメント化
  • DevilsAdvocateAgent: 未接続のまま → 削除確定 シナリオ批評は Plan で不要 (Nekoさん 明言)
削除によりエージェント数は 13 → 10、Job 数は 8 → 7 へ。

🔧 Agent → Service 化候補 (= 決定論で済むもの)

Nekoさん 指摘: 「analysis-engine に条件投げれば結果返ってくるだけだから決定論的でいい」:
  • BacktesterAgent → BacktesterService: WalkForward / MonteCarlo の並列 BT は analysis-engine 呼出のみ。LLM 判定は不要 → Service 化
  • 新規 LensFeatureService: レンズ値も analysis-engine で計算済み。Plan フェーズに値を注入するだけなのでエージェント化不要 → 新規 Service
これにより Agent (= LLM 介在) と Service (= 決定論) の境界が明確になる。
レンズの役割整理:
- Plan 側 (= LensFeatureService): シナリオ設計時に必要なレンズ値を analysis-engine から取得して planAI の input に注入。決定論。
- Action 側 (= DiscoveryAgent): 週次でレンズの insights を見て「どのレンズが効いているか」を抽出。LLM。
両者は同じレンズデータを別目的で利用する。Plan は 値を、Discovery は 解釈を使う。

🚨 Nekoさん 指摘の核心問題

P1: MutationAgent / CrossoverAgent が思った通りになっていない
現状: Evolution Loop の中で独立した変異/交配処理。input は既存 population、output は新世代 population。
Nekoさん 期待: StrategistAgent が組成した戦略案を受け取り、それをブラッシュアップする役割。
→ 解決: Evolution Loop の input 形態を変更、StrategistAgent との連結が必要。
P2: ScreeningJob / FullValidationJob / StrategistAgent の役割が不明確
現状: Strategist は fullValidationJob 内で BT 統合判定 (= ジャッジ役)。
Nekoさん 期待: Strategist は 戦略組成 が本来の役割であるべき。
→ 解決: Strategist の役割を「組成」に redefine、現状の「ジャッジ」役は決定論的な判定ロジックに分離 or 削除。
P3: 「凍結トレーダー」(= シナリオ選定者) が現状存在しない
現状: PlanAI (StrategyThinker) が Debate 結果を input にしてシナリオを書くため、選定 = 生成が暗黙に統合されている。
Nekoさん 期待: 「討論結果でシナリオをどうするか」を明示的に選ぶ役割。
→ 解決: 選択肢 (a) planAIService の prompt 拡張で選定ロジックを明示、(b) 新規 ScenarioSelector エージェント新設。
P4: Agent と Service の境界が曖昧
現状: BacktesterAgent は実態が「analysis-engine 呼出」だけなのにエージェント化 (= LLM 介在の意味合い)。
Nekoさん 期待: 決定論で済むものは Service 化、Agent は LLM 必須のものに限定。
→ 解決: BacktesterAgent → BacktesterService 化。今後の追加機能も「LLM 必須か?」で Agent/Service を判定。
P5: 不要 / 分かりにくいエージェントが残っている
DevilsAdvocate (= 未接続) / MetaEvolution (= 手動 CLI のみ) / PromptMutation (= 月次孤立 Job) は分かりにくさの原因。
→ 解決: 全てアーカイブ。必要になったら再導入。
