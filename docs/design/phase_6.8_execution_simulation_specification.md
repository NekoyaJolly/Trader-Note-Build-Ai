# Phase 6.8 — 本番執行シミュレーション層（取引所品質に近づける）

> 親: プロジェクト目標（価格・足の正は cTrader 統一。既存: `phase_6_7_overview.md` との整合）  
> 範囲: バックテスト・検証の**執行忠実度**を引き上げる設計と完了条件。Phase 6.7（即時BT＋DSL拡張＋プロンプト層）の**次段**として位置づける。  
> 依存: **Phase 6.7a〜c の完了**（少なくともマクロ展開・即時BT経路・OHLCV 品質方針が安定していること）  
> 次: 実装は本書の**完了条件**に従い段階的に。Phase 7（SMC 等）とは**直列でも並列（別チーム/別PR）でも可**だが、**コスト層**は Edge 判定・WF・MonteCarlo 全体に影響するため早期に枠を固定する。  

---

## 0. このフェーズのゴール

Phase 6.7 までのバックテストは **OHLCV 系列＋ルール系 DSL** による学習/検証分割を主とし、「次バー始値で約定」等の**簡易執行**が暗黙の前提となり得る。  
本フェーズ **6.8** は、プロジェクトに **取引所品質に近い「本番執行シミュ」** を導入する。ここでいう本番執行シimuとは、**価格系列の出所（cTrader＝ブローカー事実）**に加え、**摩擦（コスト）・執行のルール**を明示的にシミュレーションに組み込み、再現性と監査可能性を持たせることである。

### 0.1 本フェーズで「する」こと（要約）

1. **執行・コスト仮定の型**を導入（固定/時変/シナリオ）し、BT・WF・（該当する）検証ツールの出力に **仮定のタグ**を付与する。  
2. **スプレッド・手数料・（必要なら）スリッページ**を、**LLM ではなく決定論的コード**で適用する（`CLAUDE.md` 原則3）。  
3. **cTrader 由来の価格・足区切り**を正とし、コスト層はその上に**乗算・加算**で載せる（二層分離。Twelve Data 等へのフォールバックは採用しない）。  
4. 結果レポートに **「どの仮定で何を出したか」** を常に併記し、**比較可能**な主張にする。  

### 0.2 本フェーズで「まだ求めない」こと（明確化）

- **全銘柄・全執行形態の取引所マイクロストラクチャ完全再現**（オーダーブック再構築、キュー理論、部分約定の完全模倣等）は **範囲外**とし、段階的に「レベル1〜3」で定義する（§2）。  
- **真のローリング Walk-Forward**・MonteCarlo 2 系統の**コード統一**は `phase_6_7_overview` にある通り**将来/別枠**でよい。ただし **6.8 のコスト層**は将来統合されても壊れない**インターフェース**で設計する。  

---

## 1. 背景と課題

### 1.1 なぜ必要か

- エッジ台帳の `confirmed` 条件（学習/検証 PF、WF スコア等）は、**執行コスト抜きの成績**と**現実的な成績**で意味が変わる。  
- 自律エージェントに「最適化」を任せるほど、**安易にゼロコスト**に近い仮定へ吸い込まれる。摩擦を**明示的に**差し込まない限り、**再現性のある監査**ができない。  

### 1.2 制約（プロジェクト原則との整合）

- 既存の `MarketAnalysis`, `StrategyDSL`, `EdgeHypothesis`, `AgentMemory` 等を**破壊的変更しない**。拡張は**オプショナルフィールド**中心（`AGENTS.md` / `CLAUDE.md`）。  
- **数値最適化・摩擦パラメータの自動探索**の主役は Python/TypeScript。LLM は解釈とレポートに留める。  
- **人間語の `label` / `rationale`** ルール（エッジ採択系）は従来どおり。6.8 は**シミュ層**の責務。  

---

## 2. 執行シミュレーションのレベル定義

実装は段階的に進める。完了判定は**最低レベル1**、プロダクト上の「本番執行シム」宣言は**レベル2以上**を推奨。

| レベル | 名称 | 含む内容（最低限） | 代表出力 |
|--------|------|-------------------|----------|
| **1** | **摩擦ありバー執行** | 手数料（固定/ロット）, **スプレッド**（固定または時系列）, 約定: 次バー始値±スプレッド/手数料 | `executionModel: "bar_l1_v1"` |
| **2** | **拡張バー執行** | L1 + **スリッページ**（固定tick / ATR 比 / 分位）, 指値・逆指の**簡易**ルール | `executionModel: "bar_l2_v1"` |
| **3** | **高解像度** | 可能な範囲で **M1 以下**または **ティック/ベスト寄り** 系列を用いた intrabar 執行（ブローカー提供データ範囲内） | `executionModel: "highres_v1"` |

**採択方針**: レベル1は**必須到達点**。レベル2を「商用に近い」**最小定義**とし、レベル3は**シンボル・ブローカーでデータ取得が可能な場合に限定**する。  

---

## 3. 市場データの正（cTrader）と二層モデル

### 3.1 価格・時刻・足

- **OHLCV の時系列**および **取引所/ブローカーに整合する銘柄解決**は **cTrader API** を正とする（本プロジェクトの方針に合わせる）。  
- 6.8 のシミュ層は、これらのバー上に**執行ルール**を重ねる。**別データソース**で足を上書きしない。  

### 3.2 二層の責務分離

```
[ 層A: 市場マイクロ価格系列 ]  ← cTrader 由来 OHLCV（真実に近い事実系列）
         ↓
[ 層B: 執行・コストエンジン ]  ← 手数料・スプレッド・スリッページ・注文ルール
         ↓
[ 層C: 戦略/DSL 評価         ]  ← 既存 DSLBacktestAdapter 等
```

層B は **層A を入力**とし、**同じバー内で**約定価格を決定する（レベル1〜2）。レベル3 では 層A の解像度を上げる。  

---

## 4. コスト・執行パラメータ（設計上の型）

### 4.1 必須概念（型または設定スキーマとして独立）

- **commission**（向き・通貨建て or % / ロット）  
- **spread**（固定 pips/price、または**時系列**でバー毎）  
- **slippage**（レベル2以降: 定数、分布、ATR 倍率 等）  
- **session / calendar**（休場は 6.7a 方針の OHLCV に追随。**経済指標**は `phase_6_7_overview` の Phase 8+ 連携を**オプション**で参照可能にする枠だけ残す）  

### 4.2 再現性

- 同じ**シード**、同じ**設定ハッシュ**、同じ**入力系列**で、**決定論的に**同一損益系列が出ること（モンテカルロは別シードで分布）。  
- 実行結果に **`executionConfigHash`** または等価物を格納し、**後から同じ仮定を再実行**できること。  

### 4.3 スプレッドの入手方針（優先順位）

1. **ブローカー/cTrader から取得可能な実スプレッド/Quote**（将来拡張の対象。API 制約内）。  
2. **銘柄ごと固定**の保守値（`config` または DB、**人間承認**で更新）。  
3. バー高安からの**上界推定**（**レベル1 のみの暫定**に限り、文書化必須）。  

---

## 5. 既存コンポーネントへの接続方針（破壊的でない拡張）

### 5.1 `DSLBacktestAdapter` / 進化ループ

- 入力に **optional `ExecutionSimulationConfig`**（名称は実装で確定）を追加。未指定時は**現状互換**（従来の簡易執行）または**レベル1 デフォルト**のいずれかを**明文化**し、**後方互換**を保つ。  

### 5.2 `strategyBacktestService` / `walkForwardService` 経路

- Edge Validator・WF が参照する**損益系列**に、層B を通した結果を**オプトイン**で接続。  
- `confirmed` 閾値（PF, WF スコア等）は**設計書の値を勝手に緩めない**（`CLAUDE.md`）。**コスト込み**で同じ閾値か、**別レーン**（`gross` / `net`）のどちらで判定するかは**人間承認**（§6）。  

### 5.3 検証ツール（Phase 4c）

- `WalkForwardTool` / `MonteCarloTool` / `BuyAndHoldTool` の入出力に、**gross vs net** と **`executionModel` ラベル**を載せる。  
- 既存の仮説評価経路（`backtestRunId` 前提）は、Side-A との境界を壊さない。  

### 5.4 レポート

- バックテスト摘要に**必須**: `executionModel`, コスト要約, `executionConfigHash`, 使用データソース `ctrader` 明示。  
- エッジ採択（人間向け）には**ネット成績**を優先表示（UI は別タスク可）。

| # | 内容 |
|---|------|
| 1 | **レベル1 のデフォルト**（未指定時: 従来互換にするか、常に最小事前コストを載せるか） |

| 5 | 経済指標カレンダー（Phase 8+）と接続する**前**に、6.8 単体で十分な仮定セットか |

## 7. 完了条件（Phase 6.8 の「done」） 

以下を**全て**満たすこと。

1. **レベル1** の執行シミュが、少なくとも **DSLBacktestAdapter 経路**にオプトイン可能。  
2. 出力に **コスト仮定の識別子**（モデル名＋ハッシュ等）が含まれる。  
3. **cTrader 由来の価格系列**を上書きしない（二層モデルがコード構造に反映）。  
4. **ユニットテスト**: 同じ系列・同じ設定で**決定論的**な損益系列（または要約指標）が得られる。  
5. ドキュメント: 本ファイルと `phase_6_7_overview.md` または `DESIGN_DOC` のいずれかに**相互参照**（6.8 の位置づけが迷子にならない）。  
6. 既存データ構造は**破壊的変更をしない**（新規はオプショナル）。  

**レベル2 完了**を別マイルストーンにする場合、§7 の1〜6に加え、スリッページと**簡易指値/逆指**の仕様化・テストを追加する。
